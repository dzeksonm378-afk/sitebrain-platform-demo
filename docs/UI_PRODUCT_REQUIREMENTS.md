# UI Product Requirements

## Visual Style

The interface should feel like a premium dark B2B SaaS dashboard and AI control center.

Target qualities:

- modern;
- calm;
- technological;
- operational;
- readable;
- high contrast;
- visually credible during a live demo.

Avoid:

- marketing-heavy landing-page filler;
- excessive gradients;
- cluttered text blocks;
- playful consumer-app styling;
- visual elements that distract from camera/event logic.

## Dashboard Requirements

The dashboard should quickly communicate:

- connected cameras;
- AI agent status;
- recent events;
- critical safety/logistics/progress signals;
- event severity;
- event status;
- short demo narrative from camera to action.

The first viewport should make the platform understandable without scrolling.

## Page Requirements

Each core page should have a clear purpose:

- `/` - overall operational dashboard;
- `/cameras` - camera inventory and camera statuses;
- `/safety` - safety violations and dangerous zones;
- `/logistics` - warehouse zones, pallets, products, and movement;
- `/progress` - snapshots, timelapse, progress reports;
- `/events` - global event log and event lifecycle;
- `/architecture` - explanation of Camera -> AI Worker -> Event -> Dashboard;
- `/settings` - demo-mode controls and simple display settings.

## Responsive Requirements

The interface must work on:

- laptop screens;
- projector displays;
- phones opened from QR code.

Mobile does not need to feel like a native app, but it must be readable, navigable, and stable.

## Projector Readability

For live presentation:

- important text must be large enough;
- critical statuses must be color-coded and labeled;
- spacing must be generous enough for quick scanning;
- contrast must be strong;
- the main event flow must be visible at a glance.

Avoid tiny dense tables as the primary demo surface. Use compact but legible cards, rows, counters, and status chips.
